# Agent context and project history

This is the detailed, tool-neutral context behind the active rules in [`AGENTS.md`](../AGENTS.md). It was curated from the project's former Claude Code memories. Status labels matter:

- **Active**: still governs work unless the current repository proves otherwise.
- **Historical**: explains a decision or measurement; verify it before relying on it.
- **Watch**: a dated condition to remeasure, not an assertion that a problem still exists.
- **Resolved**: preserve the guardrail, but do not report the original defect as current.

## Project origin and goal

### Project origin — Active

ObsidianWikiAgent was split from LocalLLMAgent on 2026-07-01 because vault ingestion and querying are generic infrastructure, while LocalLLMAgent's calendar, email, activity, and personal-data tools are user-specific. The repositories share some operating patterns but have no code dependency. Apply a LocalLLMAgent convention here only when this repository independently needs it.

### The vault is a reasoning graph — Active

The primary learnings vault exists so LocalLLMAgent can reason across a knowledge graph, not primarily to make notes pleasant to browse. Judge changes by retrieval quality and cross-source reasoning, not page count alone.

On 2026-08-16, the write side had 390 pages, 1,734 wiki-links, two orphans, and 118/118 raw sources ingested. The consumer's former `read_wiki_index` path returned a 62 KB index into an 8 KB result cap, exposing only about 42 of 388 entries. LocalLLMAgent commit `ee7eaf5` replaced that with bounded `search_wiki` results whose observed worst case was about 4.2 KB. These numbers are historical; the invariant is that result size should scale with the answer rather than the vault.

Changes to vault shape, index semantics, summaries, or linking can affect LocalLLMAgent without failing this repository's tests. Check the consumer when those contracts change.

## Operating context

### Vault location and interpreter — Active locally

The learnings vault moved to `~/Vaults/llm-wiki-learnings` on 2026-08-13. Earlier paths in `~/Documents` and `/Volumes/T7` are historical log data. Vaults stay outside `~/Documents`, `~/Desktop`, and `~/Downloads` because macOS TCC grants are tied to the interpreter path; a Python upgrade once left a scheduled run blocked for 7h13m on an unattended consent dialog.

Entrypoints take a required `--vault` argument; code must not hardcode the local path. Use `.venv/bin/python` (Python 3.12 in the current setup), not the system Python 3.9. Personal launchd plists and vault content remain outside this repository.

### Verify current state — Active

A log proves that a condition occurred, not that it persists. Before turning a log line or old session into a finding, inspect the current artifact, its modification time, and commits made after the evidence. When they disagree, current state wins and the evidence date should be stated.

### Instructions and progress — Active

Present prerequisites before the commands they gate, in one execution-ordered sequence. For long investigations, report a two- or three-line checkpoint after a few tool calls and before slow benchmarks; otherwise ongoing work is indistinguishable from a stall.

### Git and optimization cadence — Active

This is a solo repository. When committing or pushing is explicitly requested, use `main` directly unless the user asks for a branch or pull request. Use an imperative subject, explain the concrete reason or measurement in the body, and keep one idea per commit. Vendor-specific co-author trailers are not part of the repository contract.

For optimization work, propose and land one measured change at a time. Preserve a short record of remaining ideas, but do not bundle them with the current experiment.

## Ingest and write-path decisions

### Daily synthesis files are prompts, not sources — Historical design gap

As of 2026-07-25, `Daily-Synthesis-YYYY-MM-DD.md` files were generated by LocalLLMAgent as questions or suggestions addressed to the user. Ingesting them as evidence produced weak dated pages by converting questions into claims. This is not primarily an ingest-quality bug.

The larger gap is that sources are processed independently, so ingestion does not reason across sources or days. If cross-source synthesis is requested, design it as a separate scheduled, vault-agnostic pass over `wiki/`, similar in operational shape to deep lint, rather than pretending a suggestion prompt is source material. Reverify the upstream generator and the vault's `daily-synthesis` folder before changing either repository.

### Hidden reasoning dominated wall clock — Historical, mostly resolved

The staged ingest initially appeared roughly four times slower than its single-pass predecessor. A profiled two-source run took 25.9 minutes, while logged tool activity accounted for only 38% of elapsed time. The missing time was hidden reasoning from `gemma4:26b-mlx`.

On 2026-08-21, stages 2 and 3 began passing `think=False`; stage 1 retained reasoning because disabling it harmed planning. The same workload fell to 11.2 minutes, restoring roughly four to five sources within the default 45-minute budget. Treat the budget as adequate unless current abandoned-run evidence says otherwise.

### Updates add instead of rewriting — Active design, historical measurement

Commit `e2600c8` (2026-08-21) added `edit_wiki_page` so an update supplies only new material and its destination section. Page existence on disk selects the tool: existing pages cannot receive the create/replace tool, and new pages cannot receive the edit tool. Python owns `**Sources**` and `**Last updated**`.

The follow-up run took 5m34s with no truncation, retries, or new lint findings; observed runs varied roughly 5.5-9.5 minutes based on plan size. Every deleted line across 13 updated pages belonged to deterministic metadata owned by the code. Preserve the capability boundary even if the performance numbers change.

Stage-2 concurrency was declined on 2026-08-22 because aggregate throughput did not improve under the current Ollama configuration and the local model slot is shared. Any renewed proposal starts with a current benchmark, not a concurrency implementation.

### Execute-stage link scope — Watch

Each execute conversation can link only to sibling page names in its source plan. It does not receive `list_wiki_pages`; the plan stage must include an existing page when a new page needs a backlink. Later sources still see pages created by earlier sources because planning reads the directory from disk.

The 2026-08-21 baseline was 419 pages and two orphans (`knowledge-graph-architecture.md` and `opaque-identifiers.md`) with no new broken links in the staged end-to-end run. The intended recheck date was 2026-08-28. Recompute the current baseline with `.venv/bin/python wiki_lint.py --vault ~/Vaults/llm-wiki-learnings --json` before proposing a wider plan prompt. Widen it only if current orphan growth shows the narrow scope is insufficient.

### Escaped JSON text — Resolved

On 2026-08-21, 41 damaged lines across 23 pages were repaired. Four occurrences were intentionally retained: two inside JSON fences and two prose examples discussing escape sequences. Future repair logic must distinguish syntax or examples from damaged prose.

Commit `00ddbc4` closed the ingest boundary gap in `_decode_if_escaped`; commits `680ed3c` and `88fd956` added lint detection and `--fix`. The ingest guard, detector, and fixer share `_quotes_outside_json`, so their definition cannot drift. Scheduled lint uses `--deep`, not `--fix`; repair remains explicit. Treat any old report of this defect as historical until current lint reproduces it.

## Performance reference

### Local model measurements — Historical

Measured on 2026-08-21 with an M4 Pro, 48 GB RAM, `gemma4:26b-mlx`, and Ollama 0.32.15:

- Decode was roughly 55-66 tokens/second across 1K-17K contexts.
- Prefill was roughly 700-1,200 tokens/second, about eleven times cheaper per token than decode.
- Prompt caching helped only under strict prefix extension; changing the tail caused the full prompt to be recomputed.
- One, two, and three simultaneous streams each produced about 65 aggregate tokens/second while `OLLAMA_NUM_PARALLEL` remained at its default of one.
- Hidden reasoning tokens were absent from logs, so logged tool calls did not reconcile with wall clock.

Use these as a starting hypothesis, not a current benchmark. Model, Ollama, hardware, or environment changes invalidate them.

### Deep lint provider comparison — Watch

Measured 2026-09-03 on a frozen `git archive` copy of the learnings vault (533 pages, zero structural findings), with four defects planted by hand — one per judgment category the pass claims to cover: a contradiction, a duplicate concept, an out-of-scope page, and an outdated claim. Both new pages were indexed and given inbound links so the structural pass stayed silent and only judgment was scored. Twelve trials, six per provider.

At the then-current cap of 60 iterations:

- Gemini returned `[incomplete]` in three of three runs. Each spent all 60 tool calls searching and produced no report at all.
- The local `gemma4:26b-mlx` finished three of three, using 20-23 calls and peaking at 52-58 percent of a 65,536-token window.

At a cap of 120, both providers finished every run. Gemini named 4 of 12 planted defects, the local model 2 of 12. Gemini's reports were longer and every spot-checked claim was true. The local model produced one false finding in six runs, and also one true finding the structural pass cannot reach: a corrupted in-text `(source: ...)` citation, which `check_format` does not validate because it only checks the `**Sources**` line.

Two conclusions:

1. The cap, not model quality, was the binding constraint. `MAX_DEEP_ITERATIONS` in [`wiki_lint.py`](../wiki_lint.py) was raised to 120 on the strength of this. Historical production runs used 41-56 of 60, so the headroom was already thin before the vault reached this size; remeasure as it grows.
2. Neither provider found two of the four defects in any of the twelve runs, including one on a page the local model had opened. The pass samples the vault, it does not sweep it, so a clean judgment report is not evidence that the vault is clean.

The provider itself was not changed. `LLM_PROVIDER=gemini` in the weekly lint plist remains the deliberate privacy opt-in described in [`SECURITY.md`](../SECURITY.md).

## End-to-end verification

### Test ingest changes on a fresh vault copy — Active

Unit tests alone are insufficient for model-shaped inputs. On 2026-08-21, 314 tests were green while a real ingest exposed two bugs: a whole bullet became a 319-character section heading, and a comma in a raw filename was split into two invented citations.

Build a disposable baseline from a known vault commit:

```bash
git -C ~/Vaults/llm-wiki-learnings archive <commit> | tar -x -C /path/to/fresh-copy
```

Then add only raw sources newer than that commit. Do not use a recursive copy plus `git stash`: stash does not remove untracked pages from an earlier run, which can silently turn expected creates into updates.

Compare four results with the baseline:

1. Wall clock.
2. Truncation and retry counts.
3. Newly introduced lint findings, rather than absolute lint count.
4. Per-page insertion/deletion split; each deleted line must be deliberately owned by the code.
