<!-- Reference template for a vault's git snapshot job — commits and pushes
     whatever changed in the vault, so the GitHub copy keeps up with a wiki
     that grows daily. Not itself loaded by launchd — copy it to a real
     <label>.plist (concrete .plist files are gitignored, so they stay local to
     your machine) and fill in the placeholders.

     Optional: a vault with no git remote does not need this job at all.

     Must run through .venv/bin/python, not a shell script: a vault under
     ~/Documents is TCC-protected and a launchd-spawned /bin/bash is denied
     access to it, while the interpreter that runs the ingest is not.

     Runs at 23:00, deliberately NOT just after the 09:00 ingest: an ingest
     with several new sources routinely takes one to three hours, so an
     early-morning snapshot would usually fire mid-run and commit a
     half-ingested vault — pages written but index.md and log.md not yet
     updated. An end-of-day run clears the ingest by a wide margin and also
     captures that day's hand edits in Obsidian, so a commit dated the 25th
     really does hold the 25th's work.

     For tighter recovery granularity, replace StartCalendarInterval with
     <key>StartInterval</key><integer>3600</integer> — the script exits
     without committing when nothing changed, so idle hours add no noise
     (mid-ingest commits become likely again, at the cost of a messier
     history rather than lost work).

     Placeholders to replace:
       <ABSOLUTE_PATH_TO_REPO>  where you cloned this repo
       <VAULT_NAME>             short name for the vault (e.g. learnings)
       <ABSOLUTE_PATH_TO_VAULT> the vault directory the job is pointed at
       <VAULT_BASENAME>         the LAST PATH COMPONENT of that vault directory

     The last two are usually different, and the difference is why WREN_RUN_LOG
     used to name a file that never existed: VAULT_NAME is a short label you
     pick, while setup_logger names the structured log after the vault
     directory's own basename. install.sh derives both, so run it rather than
     filling these in by hand. -->
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>local.wikiagent.<VAULT_NAME>-snapshot</string>

    <key>ProgramArguments</key>
    <array>
        <string><ABSOLUTE_PATH_TO_REPO>/.venv/bin/python</string>
        <string><ABSOLUTE_PATH_TO_REPO>/vault_snapshot.py</string>
        <string>--vault</string>
        <string><ABSOLUTE_PATH_TO_VAULT></string>
    </array>

    <key>WorkingDirectory</key>
    <string><ABSOLUTE_PATH_TO_REPO></string>

    <key>StartCalendarInterval</key>
    <dict>
        <key>Hour</key>
        <integer>23</integer>
        <key>Minute</key>
        <integer>0</integer>
    </dict>

    <key>StandardOutPath</key>
    <string><ABSOLUTE_PATH_TO_REPO>/logs/<VAULT_NAME>-snapshot.launchd.log</string>
    <key>StandardErrorPath</key>
    <string><ABSOLUTE_PATH_TO_REPO>/logs/<VAULT_NAME>-snapshot.launchd.log</string>

    <!-- WIKI_LAUNCHD_LOG: same path as the two above, so the script can cap the
         file it is writing to. launchd owns that descriptor and nothing rotates
         it otherwise. Must match StandardOutPath exactly; leave it out and
         nothing breaks, nothing gets trimmed.

         WREN_RUN_LOG: optional, and only useful if you also run LocalLLMAgent —
         its dashboard can report on this repo's jobs, and reads run history from
         the STRUCTURED log named here. Drop the key if you don't. -->
    <key>EnvironmentVariables</key>
    <dict>
        <key>WIKI_LAUNCHD_LOG</key>
        <string><ABSOLUTE_PATH_TO_REPO>/logs/<VAULT_NAME>-snapshot.launchd.log</string>
        <key>WREN_RUN_LOG</key>
        <string><ABSOLUTE_PATH_TO_REPO>/logs/vault_snapshot.<VAULT_BASENAME>.log</string>
    </dict>

    <key>RunAtLoad</key>
    <false/>
</dict>
</plist>
